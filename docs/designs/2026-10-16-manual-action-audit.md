# Аудит ручных действий бота

Цель — находить шаги, которые часто выполняются вручную, и сохранять достаточно данных для воспроизведения и улучшения парсера.

Выбран журнал SQLite в общей точке входа `BotRunner`. По сравнению с отдельным логированием в каждом handler это охватывает новые команды и все callback автоматически. По сравнению с Docker-логом таблица даёт фильтрацию по объектам, агрегацию по шагам и устойчивое хранение вместе с БД. Ранее добавленные журналы изменений отдельных полей сохраняются.

Каждое входящее действие получает запись до запуска обработки. После обработки сохраняются статус, handler, актуальный шаг и снимок значений. Ввод и callback связываются с RSS-постом, анонсом, заявкой или footer при наличии идентификатора; незавершённый ввод сохраняет контекст диалога и ссылку. Удаление сохраняет предыдущие значения. При ошибке после фактической записи в БД снимок показывает реальное состояние, а статус остаётся `error`.

Статус `handled` означает завершение handler без исключения, но не гарантирует бизнес-изменение. Повтор того же шага ввода выделяется как `awaiting_input`. Исключения не подавляются; при сбое финального аудита исходное исключение сохраняется, а запись остаётся незавершённой. Если не удалось создать начальную запись, бизнес-действие не выполняется.

Безопасность: новые внешние endpoint отсутствуют, существующая авторизация не меняется. SQL параметризован, regex имеют таймаут. Тексты и снимки запрещённых действий не сохраняются, распространённые форматы секретов маскируются. Журнал содержит пользовательские данные, доступ к нему определяется правами на рабочую БД. Он не передаётся модели. Сообщения об исключениях не записываются.

Проверки покрывают полный ручной ввод, заявки и модерацию, редактирование и удаление, черновики автоматики, footer, отмену, ошибочный ввод, запрещённые действия, исключения, сбои аудита, маскирование и совместимость со старой БД. Скрипт отчёта использует SQLite только для чтения. Операционные команды и ограничения описаны в `docs/operations/manual-actions.md`.
