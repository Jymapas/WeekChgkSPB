# Проверка безопасности 22.10.2026

Проверены прямые и транзитивные NuGet-зависимости основного и тестового проектов, маршрутизация Telegram-команд и диалогов, проверки авторства, формирование HTML, SQL, загрузка RSS/backfill и работа с секретами. Проверка относится к приложению; аудит ОС, Docker daemon и истории всех секретов не проводился.

## Исправления

| Уровень | Проблема | Исправление |
| --- | --- | --- |
| High advisory, ограниченная применимость | `SQLitePCLRaw.lib.e_sqlite3 2.1.10`: CVE-2025-6965, повреждение памяти при специально составленном SQL. Приложение не предоставляет выполнение произвольного SQL | `Microsoft.Data.Sqlite 9.0.21`, `SQLitePCLRaw.bundle_e_sqlite3 3.0.5`, нативная `SQLite 3.54.1`. Старый `lib.e_sqlite3` отсутствует в восстановленном графе |
| Высокий | Footer-команды были скрыты из пользовательского меню, но не все обработчики проверяли чат. Посторонний пользователь мог добавлять и удалять строки будущих публичных публикаций | Общая проверка `BotCommands.AdminOnly` перед вызовом обработчиков. Административные диалоги дополнительно проверяют чат на каждом шаге; при отказе состояние удаляется |
| Средний | Название, площадка, текст стоимости и URL анонса интерполировались в HTML. Редактор мог подменить разметку/ссылки либо сорвать публикацию. Опасные URL могли попасть в HTML для ЖЖ | HTML-экранирование значений и атрибутов в обоих форматах публикации. Ссылки с иными схемами, чем HTTP/HTTPS, выводятся обычным текстом. Административные footer-строки по-прежнему поддерживают HTML |

Отказы сохраняются в `manual_actions` без ввода и снимков, включая попытки продолжить административный диалог в другом чате. `/cancel` остаётся доступной в любом чате. Права обычных пользователей на собственные анонсы и права по привязкам ЖЖ сохранены.

## Проверка

- До исправления 21 регрессионный сценарий воспроизводил отсутствие запрета/экранирования.
- Полный локальный прогон: 365 .NET-тестов и 12 Python-тестов прошли, Telegram заменён заглушками.
- Отдельный тест открывает настоящую SQLite и проверяет `sqlite_version() >= 3.54.1`, а не только версию NuGet-пакета.
- На изолированной копии продовой БД с новым нативным движком прошли 15 проверок привязок, прав, редактирования, удаления, аудита, запрета повторного создания и `integrity_check`.
- `dotnet list WeekChgkSPB.sln package --vulnerable --include-transitive --format json`: известных уязвимых NuGet-пакетов не найдено. Это результат текущей базы advisory, а не гарантия отсутствия неизвестных проблем.
- SQL использует параметры; динамические имена колонок берутся из констант кода. Пользовательского SQL и загрузки расширений нет.
- RSS запрещает DTD/внешние XML-сущности и ограничивает размер. Backfill ограничивает HTTPS, домен сообщества, перенаправления, время и объём ответа. TLS-проверка не отключена.
- Проверка типовых шаблонов Telegram-токенов, access keys и private keys в отслеживаемых рабочих исходниках (без тестовых фикстур) не выявила совпадений. `.env` не отслеживается Git.

## Оставшееся обслуживание

На проде проверен runtime .NET 9.0.21. Поддержка .NET 9 заканчивается 10.11.2026; до этой даты следует запланировать переход на .NET 10 LTS. Это срок сопровождения, а не обнаруженная уязвимость текущего runtime. Локальный установленный runtime 9.0.10 старее продового; его обновление не входит в изменение приложения.

База содержит пользовательский ввод и аудит; права доступа и резервные копии БД остаются операционной ответственностью. Публичные footer-строки являются доверенным HTML администратора.

## Первичные источники

- [CVE-2025-6965 / GHSA-2m69-gcr7-jv3q](https://github.com/advisories/GHSA-2m69-gcr7-jv3q): исправление SQLite начиная с 3.50.2; в старой линейке нативного NuGet-пакета исправленной версии нет.
- [SQLitePCLRaw 3: примечания автора](https://github.com/ericsink/SQLitePCL.raw/blob/main/v3.md): замена нативного пакета при сохранении провайдера `e_sqlite3`.
- [SQLite 3.54.1](https://sqlite.org/releaselog/3_54_1.html), [статус CVE SQLite](https://sqlite.org/cves.html).
- [.NET: политика поддержки](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).
