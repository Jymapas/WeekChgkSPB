# Редактирование анонсов авторами ЖЖ

Бот сопоставляет Telegram-пользователей с числовыми идентификаторами авторов ЖЖ. Один аккаунт ЖЖ можно связать с несколькими редакторами, а одного редактора — с несколькими аккаунтами. Привязки хранятся в `telegram_lj_users`, авторы исходных записей — в `lj_post_authors`. Авторство хранится независимо от `posts`, поэтому оно сохраняется после очистки RSS и работает для анонсов с внешней ссылкой и другим внутренним ID.

Существующие права администратора и владельца по `announcements.userId` сохраняются. Дополнительные права через ЖЖ действуют в личном чате: пользователь должен находиться в `allowed_users`, отсутствовать в `banned_users` и иметь привязку к автору исходной записи. Создатель анонса в `userId` при привязке не меняется. Имя турнира, место и контакты внутри текста не дают прав редактирования.

## Управление привязками

Команды выполняются только в настроенном админ-чате:

```text
/lj_bind <telegram_id> <lj_login> [--allow]
/lj_unbind <telegram_id> <lj_login>
/lj_list [telegram_id]
```

`/lj_bind` разрешает логин по уже полученным метаданным ЖЖ. Неизвестный или неоднозначный логин не связывается. Без `--allow` команда не меняет белый список; флаг явно добавляет пользователя в него. Бан команда не снимает. Удаление привязки не удаляет пользователя из белого списка и не затрагивает другие его связи.

После наполнения авторства начальная настройка выполняется однократно:

```text
/lj_bind 205237145 alfakentavra
/lj_bind 468975002 igry_razumaspb --allow
```

При следующих запусках приложения эти привязки автоматически не восстанавливаются.

## Восстановление авторов старых записей

Новые и уже известные записи из RSS получают автора при каждом обходе ленты, включая режим `off`. Метаданные записываются до пропуска анонсов, которые уже существуют. Отсутствующие или противоречивые данные не затирают известный числовой ID автора.

Для исторических источников используйте Python 3 и согласованную SQLite-копию. Сначала получите отчёт:

```bash
python3 scripts/backfill-lj-authors.py --db /path/to/posts.db
```

По умолчанию БД открывается с `mode=ro`: таблицы и привязки не создаются, данные не изменяются. Для сохранения подтверждённых метаданных:

```bash
python3 scripts/backfill-lj-authors.py --db /path/to/posts.db --apply
```

Утилита сначала читает текущий RSS, затем страницы сохранённых источников из `posts` и `external_posts`, автор которых ещё неизвестен. Для страницы используется JSON `Site.entry` из служебного скрипта непосредственно в `head` или `body` документа. Проверяются сообщество `chgk_spb` и ID конкретной записи. Содержимое `article`, комментарии и произвольные упоминания пользователей не рассматриваются как авторство. Уже сохранённый другой числовой ID не заменяется даже при изменении БД между чтением и записью.

Отчёт JSON содержит источник, логин/ID при успешном распознавании и статус:

- `would_save`: метаданные найдены, запуск был без `--apply`;
- `saved`: метаданные сохранены;
- `unchanged`: автор уже известен;
- `conflict`: данные расходятся с сохранённым автором или источником;
- `unresolved`: метаданные не распознаны или загрузка не удалась.

Неуспешные случаи не получают новых прав. Утилита записывает только `lj_post_authors`, не создаёт Telegram-привязки и не добавляет пользователей в белый список. Она не вызывает Qwen или Telegram. Загрузчик использует HTTPS, проверяет сертификаты, домен и каждое перенаправление, ограничивает время запроса и размер ответа. Если Python не доверяет сертификату сервера или сетевого прокси, настройте доверенное CA-хранилище через `SSL_CERT_FILE`; проверку TLS отключать не нужно.

## Редактирование, удаление и аудит

Редактор использует существующие `/edit_name`, `/edit_place`, `/edit_datetime`, `/edit_cost` и `/delete` с исходной ссылкой. Права проверяются заново при завершении диалога; диалог привязан к чату, из которого он начат. Отозванная привязка или бан не позволяют завершить ранее начатую правку.

Успешные изменения обновляют последний сводный пост канала. Изменения полей сохраняются в `announcement_edits`, команды и отказы — в `manual_actions`; запрещённый ввод сохраняется без содержимого и снимков данных.

Ручное удаление создаёт `announcement_deletions` вместе с удалением анонса одной транзакцией. Запись остаётся после очистки RSS и предотвращает повторное создание автопарсером или старым черновиком. Явное ручное добавление доступно по прежнему сценарию.

Проверки утилиты без сети:

```bash
python3 -m unittest discover -s Tests/scripts -p 'test_backfill_lj_authors.py' -v
```
